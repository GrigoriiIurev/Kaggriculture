# Replay Warehouse

Replay Warehouse собирает все завершённые игры одной Kaggle-отправки и готовит
данные для следующих моделей. Сырые replay не включаются в Git.

## Colab

Откройте `kaggriculture_replay_warehouse_colab.ipynb`, задайте:

```python
SUBMISSION_ID = 55680902
TEAM_NAME = "Grigorii IU"
MAX_REPLAYS = 0
```

`MAX_REPLAYS = 0` означает все доступные игры. Повторный запуск обращается к
Kaggle, сравнивает episode ID и скачивает только отсутствующие replay.

Результаты находятся на Drive:

```text
MyDrive/Kaggriculture/replay_warehouse/submission_<ID>/
├── episode_index.json
├── replays/
└── analysis/
    ├── episodes.csv
    ├── trajectory_profiles.csv
    ├── daily_macro.jsonl.gz
    ├── market_decisions.jsonl.gz
    ├── manifest.json
    └── report.md
```

## Файлы

`episode_index.json` содержит список завершённых эпизодов, время игр и метаданные
отправки. При `MAX_REPLAYS > 0` анализируются только ID из этого индекса, даже
если в папке остались другие JSON.

`episodes.csv` содержит одну строку на траекторию нашего агента: результат,
соперника, сторону, денежную динамику по фазам, тип стратегии соперника и
диагностический ярлык поражения.

`trajectory_profiles.csv` содержит обе стороны каждой игры. В нём находятся
пиковое количество животных, культур, работников и земли, покупки и продажи,
а также эвристический тип стратегии. Действия победившего соперника поэтому не
теряются и могут стать учительскими данными.

`daily_macro.jsonl.gz` содержит одну строку на игрока в игровой день: компактное
состояние в начале и конце дня, изменение денег и агрегированные полевые и
рыночные действия. Это заготовка для дневной макрополитики.

`market_decisions.jsonl.gz` содержит одну строку на игрока в ход: компактное
состояние, рыночные заявки, изменение денег на следующем состоянии, итог игры и
признак победителя. Это заготовка для market policy и value model.

`report.md` — читаемый итог: W-T-L, влияние стороны, результаты против разных
типов соперников, фаза возникновения дефицита и десять худших поражений.

## Важно

Ярлыки `late_market_or_liquidation`, `opponent_production_scale` и аналогичные
являются эвристиками. Они показывают, какой replay исследовать первым, но не
доказывают причинно-следственную связь.

Полный replay занимает примерно 30 MB. Для 140 игр требуется около 4–5 GB места
на Google Drive. Компактные аналитические файлы значительно меньше.
