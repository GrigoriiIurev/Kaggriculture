# Worker Planner

`WorkerPlanner` превращает задачи из `TaskGenerator` в одну команду для каждого
работника на текущем ходу.

```python
from state_parser import parse_observation
from task_generator import TaskGenerator
from worker_planner import WorkerPlanner

generator = TaskGenerator()
planner = WorkerPlanner()


def agent(obs):
    state = parse_observation(obs)
    tasks = generator.generate(state)
    plan = planner.plan(state, tasks)
    return plan.action
```

Эта цепочка уже подключена в `main.py`.

## Фазы работника

Каждый `UnitDecision` содержит текущую фазу:

- `IDLE` — подходящей задачи нет, команда `PASS`;
- `MOVE_TO_SHED` — работник идёт к ближайшему входу в сарай;
- `PICKUP_ITEM` — забирает нужный предмет, например `WHEAT`;
- `MOVE_TO_TASK` — идёт к целевой клетке;
- `EXECUTE_TASK` — находится на клетке и выполняет команду задачи.

Пример пути для кормления:

```text
MOVE_TO_SHED -> PICKUP WHEAT -> MOVE_TO_TASK -> FEED
```

## Назначение задач

Задачи рассматриваются от большего приоритета к меньшему. Для очередной задачи
выбирается свободный работник с самым коротким маршрутом. Небольшой бонус
получает работник, который уже шёл к этой задаче на предыдущем ходу.

Новая задача с большим приоритетом всё равно может прервать старый маршрут.

Планировщик учитывает предметы в инвентарях и резервирует содержимое сарая. Если
в сарае лежит одна пшеница, только один работник получит маршрут с `PICKUP`.

Экономический планировщик может закрепить задачу за конкретным работником. Это
используется для `DROP`: к сараю должен вернуться именно тот работник, в рюкзаке
которого лежит урожай.

## Движение

На карте нет непроходимых препятствий: работники могут находиться вместе и
проходить через закрытые клетки. Поэтому используется кратчайший манхэттенский
маршрут, сначала по горизонтали, затем по вертикали.

```text
distance = abs(worker.x - target.x) + abs(worker.y - target.y)
```

## Текущее ограничение

За один ход назначается только одна операция на клетку. Это предотвращает
опасный порядок вроде `HARVEST`, удалившего одноразовое растение до `WATER`.
Позже можно добавить таблицу совместимых операций и выполнять, например,
`FEED` и `CARE` на одном животном за один ход.

Сам `WorkerPlanner` не нанимает работников и не создаёт рыночные заказы. Это
делает `EconomicPlanner`, а `main.py` объединяет его рынок с командами
работников.
